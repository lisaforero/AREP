# Microframework Web

This project is a lightweight, custom Java-based web framework designed to make building web applications simple and efficient. It allows developers to define how the app responds to requests using Lambda expressions, while clearly separating dynamic services like REST APIs from static files such as images. It also includes its own request handling system to process user inputs, ensuring that static content loads properly without issues like broken image icons.

## Architecture

### 1. Request handling and parsing

The core of the framework is the `HttpServer` class, which manages a `ServerSocket` on port `8080`. It uses a **custom HTTP Parser** that performs the following:

* **URI analysis:** It breaks down the HTTP request line to extract the path and the query string.
* **State management:** It wraps the query parameters into a specialized `HttpRequest` object, making them easily accessible for developers via keys.

### 2. Hybrid routing engine

The framework uses a **Map-based routing** system to decide how to process an incoming request:

* **Dynamic layer (APIs):** A `HashMap` stores `WebMethod` implementations (Lambdas). The engine features a **Flexible prefix resolver**: if a request comes in as `/app/service` or just `/service`, the engine intelligently maps it to the same logic, providing versatility to the developer.
* **Static layer (File system):** If no dynamic route matches, the engine switches to the static handler. This layer is intentionally separated from the `/app` prefix to distinguish between logical endpoints and physical assets.

### 3. Resource loading

To ensure portability, the framework does not rely on absolute OS paths. Instead, it leverages the **Java ClassLoader**:

* It fetches resources directly from the `src/main/resources/webroot` path.
* This allows the framework to serve files correctly even when the project is packaged into a JAR or moved to a different environment.

### 4. Binary-safe response stream

To support various media types (like `.png` or `.jpg`), the architecture separates the response flow:

* **Text response:** Uses `PrintWriter` for dynamic HTML generated by lambdas.
* **Binary response:** Uses `BufferedOutputStream` for static files. By writing the raw bytes directly to the socket, it avoids the encoding issues that typically corrupt images when handled as plain strings.

## How to run

### 1. Prerequisites
Make sure you have the following installed:

- Java SDK 17 or higher.

- Apache Maven.

### 2. Installation
First, clone this repository and enter the project directory:

```
git clone https://github.com/lisaforero/Microframework_web.git
cd Microframework_web
```

### 3. Build the project
Compile the code and prepare the resources using Maven:

```
mvn clean compile
```

### 4. Start the server
Run the application with the following command:

```
mvn exec:java
```

You will see the following output in your terminal:

```
Ready to receive ...
```

The server will be active at: http://localhost:8080

## Test examples

- http://localhost:8080/app/pi	Returns 3.1415... (Works with or without /app).
- http://localhost:8080/app/hello?name=Lisa	Returns "Hello Lisa" (Parses query params).
- http://localhost:8080/index.html	Loads the page from the resources folder.
- http://localhost:8080/cat.png	Renders the image perfectly (Binary safe).

_Note:_ Static files are served from the root. Adding the /app prefix to a file request (e.g., /app/cat.png) will correctly return a 404 Not Found, as /app is reserved for registered services.
